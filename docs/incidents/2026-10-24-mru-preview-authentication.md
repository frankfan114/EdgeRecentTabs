# 2026-10-24：最近标签顺序异常与预览缺失

- 状态：已恢复，用户已确认正常。
- 日期：2026-10-24（Europe/London）。
- 范围：Edge 扩展与 Hammerspoon 本地桥接；未清除浏览器存储或重新安装扩展。

## 现象

切换面板仍能打开，但标签按浏览器里的排列顺序显示，而不是按最近访问顺序显示；预览全部为空。这容易被误认为 MRU 缓存损坏。

## 根因

**运行中的 Edge 扩展与已经更新的 Hammerspoon 使用不同的桥接 token。** 更新磁盘文件不会自动重新加载 Edge 的扩展 service worker。Hammerspoon 已安装并启动新配置，Edge 仍在发送不匹配的凭据，消息因此被拒绝。

最初还发现源码扩展使用 token 占位符，而已安装的 Lua 使用私有 token。对源码 token 发出的 HTTP 诊断请求得到 403，但当时无法读取 Edge 的实际加载路径，因此这一检查本身不能证明运行中的扩展来自哪个目录。随后生成并安装了匹配的文件，但两端运行状态尚未同步。

没有扩展快照时，Hammerspoon 的 AppleScript 备用路径会按窗口、标签索引枚举当前打开的标签。这只是可用标签列表，不是真正恢复的浏览历史；它也不提供截图。因此，一处桥接认证失败可以同时解释“顺序像从上到下”和“没有预览”。

另一个诊断缺陷是：旧代码在校验 WebSocket 消息 token **之前**就更新最近通信时间。错误凭据的连接也可能被算成健康连接，掩盖了真实问题。

## 修复与恢复步骤

1. 生成两端共用的私有 token。扩展从 Git 忽略的 `bridge-token.js` 读取；源码扩展目录和 `dist/edge-extension` 都能使用。重复生成保留现有 token，删除 `dist` 后也可从源码目录的私有配置恢复。
2. 备份、安装并重启 Hammerspoon。用户在 `edge://extensions` 重新加载原来的 Edge MRU Bridge，保留扩展 ID、设置和本地历史。
3. 修正桥接健康判断：缺失或错误 token 的 WebSocket 消息不能刷新健康状态。
4. 增加只返回连接状态、消息类型和计数的 `/status` 诊断接口，不返回页面标题、URL 或 token；诊断只在请求时运行，没有新增后台轮询。
5. 实测普通网页能够生成并传送预览，随后由用户确认功能恢复。

预览仅缓存在内存中。扩展重载或 Hammerspoon 重启可能使预览暂时为空；重新访问普通网页并停留片刻后会补回。受保护的浏览器页面不能作为截图链路的验证页面。此次没有证据表明持久化 MRU 存储损坏，也不需要清空它。

## 验证与此前的检查缺口

此前仅验证了生成文件的 token 一致、本地 HTTP 接口返回 200，以及模拟浏览器的回归测试。这些结果没有证明 Edge 实际运行的 worker 已更新，也没有证明截图能端到端送达。这是本次排查遗漏，不能把“TCP/WebSocket 已连接”或“本地认证探针成功”当作功能恢复。

补充验证包括：

- 执行真实生成的 token 脚本，不再只在 mock 中注入 token。
- Lua：拒绝旧凭据、认证后的健康状态、扩展快照顺序和激活事件更新顺序。
- JavaScript：按不连续的访问顺序切换标签，确认 MRU 与发送的快照保持访问顺序，而非标签索引顺序。
- JavaScript：仅捕获前台活动标签、缩略图缩放、原始位图释放、50 张缓存上限、捕获错误后恢复。
- 实机：扩展重载后收到真实 MRU 快照；临时普通网页产生真实预览；用户确认恢复。

## 同次更新中的快捷键改动

快捷键问题与这次认证故障分开处理：复用已有的键盘事件监听器处理 Option+Tab，只在 Edge 焦点窗口启动；其他应用放行按键，离开 Edge 取消切换。松开 Option 直接提交选择，原有 20 ms 检查仅在切换面板打开时作为兜底。

继续保留 MRU、窗口范围、预览、图标、方向键、数字键和 Escape 功能。没有增加键盘监听器或空闲轮询；预览上限仍为 50 张，每张最大 520×320。性能检查证明无关的空闲按键不查询应用或窗口、不新增定时器；这不是实机端到端延迟或 RSS 内存基准。macOS Secure Input 对事件监听器的限制仍适用。
